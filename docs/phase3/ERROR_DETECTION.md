# Python error detection

Code mode combines three detection sources:

- Python tokenization, AST parsing, and compilation report syntax/indentation errors, including invalid statements such as `return` outside a function. Compilation creates bytecode but never executes uploaded code. Only the first Python syntax error is reported; fix it and check again to find subsequent errors.
- Isolated Ruff checks detect common undefined names, unused imports, mutable defaults, and other configured F/B/S rules.
- Ollama reviews selected source excerpts for potential logic issues. Its findings require valid source IDs and line ranges. Model findings remain suggestions requiring verification.

Requests containing “fix”, “correct”, or “debug” now use the code-review route, alongside existing review/error requests. This step detects issues; it does not generate replacement code.

`POST /api/chat` includes Python syntax findings in `findings` with `tool: python`, the exception type in `rule`, filename, line, column, message, reasoning, and source IDs. `analysis.syntax_checks` reports the parser status per file. Existing `analysis.checks` reports Ruff status separately. Syntax findings are retained and cited on follow-up and appear under “Python syntax errors” in the reply. Duplicate Ruff syntax findings are omitted when Python supplies a syntax error.

Parser diagnostics remain available when Ruff fails. The chat endpoint still requires a successful model response before returning and saving its combined answer. Resource limits and unsupported source line mappings produce explicit warnings; a successful syntax check does not establish runtime correctness. Python syntax support follows the installed interpreter.

Tests include real Ruff checks, parser/compiler error locations, null Ruff syntax codes, checker failure, non-execution, API citations, persistence, follow-ups, and review routing. ## Original code and issue locations

Each finding now includes `code_excerpt`, read from its authorized source file rather than generated by Ollama. It contains `lines` (objects with `line` and `code`) and `truncated`. Excerpts preserve indentation and Unicode, normalize CRLF/CR line endings, and reconstruct lines split between stored spans. Excerpts are capped at eight lines and 2,000 code characters per finding, with explicit truncation text in the reply. Unsupported line mappings return null rather than guessed code.

The reply shows the filename, line/column, issue message, numbered original code, and reasoning for Python, Ruff, and model findings. These details are also retained in saved analysis results and recomputed from retained sources on follow-up. Existing plain-text browser rendering, copying, and downloads include the same report.

Verification for this step: 90 tests passed across `test_python_analysis.py`, `test_ruff_analysis.py`, `test_model_findings.py`, and `test_text_answers.py`. Cases cover source-derived snippets for all three finding types, findings outside model excerpts, split lines, blank-line gaps, Unicode, indentation, excerpt limits, unsupported mappings, source scoping, persistence, and follow-ups. No live model evaluation was performed.

## Suggested corrections

Code answers can now include up to four corrections with `source_id`, `start_line`, `end_line`, `replacement_code`, and `explanation`. The source range is inclusive and describes complete original lines to replace. Code and explanation are capped at 4,000 and 1,000 characters respectively. The controller rejects unknown sources, invalid ranges, blank fields, excess corrections, and overlapping edits to the same file, including overlaps across different source spans. The model request schema restricts source IDs to the current evidence and limits answer citation counts to the number of available IDs.

The server supplies filenames and original code excerpts, restores omitted indentation for single-line statements when a complete original line is available, adds correction citations, and saves suggestions with the successful analysis result. The reply displays detected issues before suggested replacements and explanations. The uploaded original remains unchanged. Suggestions use `validation_status: not_checked`; syntax/Ruff validation of proposed changes is the next step. The model may return no correction when context is insufficient. Suggestions are restricted to model-selected excerpts; no separate correction pass is performed for Ruff findings outside them.

Verification: the correction, model-finding, answer/API, and agent tests passed. This check explicitly identifies the target line in its prompt; it verifies generation and formatting for that example, not general correction accuracy. ## Correction validation

Corrections are now applied together per file to a reconstructed in-memory copy. Edits use inclusive original line ranges and are applied from the bottom upward so multiline replacements do not shift subsequent targets. Original stored sources stay unchanged. Python tokenization, parsing, and compilation check the resulting full file; isolated Ruff reruns the configured F/B/S rules. Neither step executes the proposed program.

Each correction's `validation_status` is now one of `checks_passed`, `syntax_error`, `issues_remaining`, `incomplete`, or `invalid_edit`. `analysis.correction_validation` contains per-file syntax diagnostics, Ruff findings, checker status, and truncation information. These results are saved with the analysis and displayed after the proposed replacements. Reported diagnostic line numbers refer to the proposed file, rather than original-file citations. All edits for a file share its validation result.

Validation uses one five-second budget across files, a maximum three-second Ruff timeout per file, and existing parser input/resource limits. Unsupported source mappings, unavailable/time-limited checkers, and truncated results cannot produce `checks_passed`. Passing means syntax and configured static checks passed; it does not establish logical correctness or successful runtime behavior. Model proposals are still suggestions and are not applied to the uploaded original.
